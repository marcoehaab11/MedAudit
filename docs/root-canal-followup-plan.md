# خطة حشو العصب واستكمال العلاج — 8 نوفمبر 2026

## ما وجدناه قبل التعديل

الشاشة تحفظ رقم المرحلة والقنوات وبيانات الكراون في سجل الزيارة، وتعرض العلاجات الجارية في الزيارة التالية. لكنها لا تملك سجلًا ثابتًا لكل خطوة، والحشو الخارجي والدعامة والكراون مدمجون في حالة واحدة. مسار الحسابات الحالي يستطيع إنشاء تكلفة قبل اكتمال العلاج.

## خطة التنفيذ

1. إضافة سجل خطوات معتمد من الخادم لكل علاج وسن: الحالة، وقت الحفظ، الزيارة والطبيب. حفظ كل خطوة واستكمال أول خطوة غير مكتملة، مع الاحتفاظ بسجلات الزيارات السابقة.
2. ترتيب المسار: فتح الحجرة، الأطوال والملفات، حشو القنوات، الحشو الخارجي. الحشو المؤقت يُسجل كتنفيذ مستقل ويترك الحشو الدائم مطلوبًا.
3. بعد الحشو الدائم، يختار الطبيب الدعامة والكراون بنفسه. التخطيط لا يُنشئ تكلفة. الدعامة لها إكمال مستقل، والكراون يحتفظ بكل خطواته، مع الكراون المؤقت كخطوة اختيارية.
4. ربط الإجراءات المنفذة بقائمة أسعار العيادة. يُفوتر حشو العصب عند إتمام حشو القنوات، والحشو المؤقت عند تسجيل تنفيذه، والحشو الدائم عند إتمامه، والدعامة عند إتمامها، والكراون عند التثبيت النهائي. المراحل التحضيرية لا تُفوتر ككراون مكتمل.
5. استخدام سجل علاج رئيسي للمتابعة، وإجراءات مرتبطة به للحسابات، مع قيد يمنع تكرار نفس الإجراء. اختيار خدمة من قائمة الأسعار مطلوب؛ لا يخترع البرنامج سعرًا أو يجمع خدمات باقة قديمة مرتين.
6. إظهار «متابعة العلاج» في بداية الزيارة برقم السن والنوع والمرحلة والحالة، وفتح نفس العلاج عند أول خطوة ناقصة.
7. اختبار أكثر من سن وأكثر من زيارة، والحشو المؤقت ثم الدائم، واختيارات الدعامة والكراون، وإعادة الحفظ، والطلبات المتزامنة، والصلاحيات وعدم تكرار الحسابات.

تحديث قاعدة البيانات يُجهز كملف قابل للمراجعة. لا تعديل تلقائي للفواتير القديمة أو نشر على الموقع الحي أثناء التنفيذ المحلي. الأسعار التاريخية والإجراءات المنفذة سابقًا لا يعاد تسجيلها تلقائيًا كإجراءات جديدة.

## حالة العمل

تم تنفيذ المسار المحلي واختباره: 232 اختبار وحدة للخادم، و115 اختبار واجهة، و25 اختبار تكامل وحماية بيانات، و3 اختبارات لبنية المشروع. نجح بناء الواجهة والخادم، وأكدت أداة قاعدة البيانات أن تغييرات الجداول ممثلة في ملف التحديث الجديد.

اختبار قاعدة البيانات أثبت الاستكمال عبر ثلاث زيارات، وتسجيل خمسة إجراءات مكتملة مرة واحدة لكل إجراء، وعدم فوترة الدعامة والكراون المخططين، وحفظ واحد عند إرسال طلبين متزامنين. ملفات هذا الاستكمال مرفقة مع تحديث الكود؛ لم تُطبّق تغييرات على قاعدة البيانات الحية.

الباقات القديمة أو الخطط التي سبق احتسابها تحتاج مراجعة أسعار قبل إضافة بنود جديدة؛ لم تُعدّل الفواتير التاريخية أو تُقسّم أسعارها تلقائيًا. التفاصيل وخطوات التجربة في [تقرير التنفيذ](root-canal-followup.md).
